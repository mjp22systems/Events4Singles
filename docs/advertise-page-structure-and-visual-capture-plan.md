# Advertise Page Structure And Visual Capture Plan

Last updated: 2026-08-29

## Purpose

The advertise page should sell real Events4Singles visibility, not generic marketing mockups. Every visual must show where an advertiser appears in the live site layout, with enough surrounding page context to understand proportion, position, and value.

The page structure is broadly correct. The work now is to refine content, pricing, package logic, and replace temporary reconstructed previews with full-context captures or generated visuals based directly on live page structure.

## Locked Page Structure

1. Hero
   - Role: lead-in pitch plus one annotated page preview.
   - Keep the concept of labelled placement overlays.
   - The visual must be a full-context page view, preferably a city/category or homepage section that naturally contains listing rows, event cards, and the right column.
   - Do not use a cropped isolated card as the hero visual.

2. Placement Explorer
   - Role: interactive comparison of major advertising placement families.
   - Keep as the detailed decision tool.
   - Each tab should show the relevant page context, not a generic component sample.

3. Available Positions
   - Replaces the vague "Inventory" framing.
   - Role: catalogue of sellable units grouped by page context.
   - Groups: Listing results, page furniture, event pages, homepage.
   - This section should explain what is sold and where it appears.

4. Packages
   - Role: pricing and plan selection.
   - Keep layout, refine package names and inclusions later.
   - Pricing should support launch growth: free listing first, then clear upgrade points.

5. Portal Workflow
   - Role: show how advertisers get from free listing to paid placement.
   - Keep the process visual.
   - Final flow should match the actual portal: create/claim, choose placement, upload creative, review/publish, track results.

6. Recommended Campaigns
   - Current page calls this Bundles.
   - Keep only if fixed bundles are real products.
   - If bundle pricing is not locked, rename to Recommended Campaigns and present them as suggested combinations.

7. Creative Support
   - Role: reassure small advertisers that rough source material can be adapted.
   - Keep.

8. Trust And Control
   - Role: explain review, sponsored labels, and advertiser responsibility.
   - Keep.

9. Final CTA
   - Role: start free listing or plan campaign.
   - Keep.

## Visual Capture Rules

1. Capture full context first.
   - A visual should show the page area the advertiser is buying within.
   - For a sidebar ad, show listings to the left and the sidebar to the right.
   - For sticky listing, show the full listing stack width with at least one normal listing below it.
   - For top banners, show the header/nav area and the content immediately below.

2. Highlight the placement, not the whole screenshot.
   - Use a frame, tint, label, or callout around the paid position only.
   - Leave surrounding page content visible and unwarped.

3. Preserve site proportions.
   - Listing rows stay horizontal and wide.
   - Event cards stay in their actual grid relationship.
   - Sidebar units stay narrow relative to listing content.
   - Homepage tiles stay in the real homepage tile layout.

4. Do not force every advertising type into the same card size.
   - Wide placements need wide preview containers.
   - Right-column placements need a layout showing their relationship to the main content.
   - Event grids need enough width to show multiple cards.

5. Avoid browser chrome unless it helps context.
   - Use full page or section captures from the site.
   - Only wrap in a browser frame for the hero or a major overview visual.

6. Do not use old legacy screenshot images.
   - Use live site captures, rebuilt UI screenshots, or AI-generated assets that preserve the real site layout.
   - If AI is used, it must reconstruct from the live layout and maintain proportions.

## Required Capture List

### Hero Annotated Overview

- Source page: homepage mid-section or a city/category page with listings and right column.
- Capture type: wide desktop screenshot, full page section.
- Must show: site header, What&apos;s On or listing results, Featured Businesses/listings, standard listings, sticky/featured position, and right column if present.
- Highlight: only the labelled sellable zones visible in that view.
- Advertise page use: hero visual.

### Standard Listing

- Source page: city/category listing results.
- Capture type: full listing-row width plus page margins.
- Must show: one standard listing in context with neighbouring listings.
- Highlight: standard listing row.
- Avoid: placing this in a narrow third-column card.

### Featured Listing

- Source page: city/category or homepage Featured Businesses section.
- Capture type: full listing-row width.
- Must show: featured treatment relative to normal rows.
- Highlight: featured card/badge area.

### Sticky Listing

- Source page: city/category listing stack.
- Capture type: full listing stack width.
- Must show: pinned listing above at least one normal listing.
- Highlight: pinned position and label.
- Avoid: isolated small card with no surrounding stack.

### Page-Top Banner

- Source page: city/category page, or profile/detail page if banner appears there.
- Capture type: wide section including header/nav, banner, and first content below.
- Must show: banner position relative to page content.
- Highlight: banner strip only.

### Right-Hand Column Advertising

- Source page: city/category page with listing column plus right sidebar.
- Capture type: desktop two-column section.
- Must show: listings/content on left and refine/sponsored/sidebar ad stack on right.
- Highlight: right-hand advert area.
- Avoid: screenshot of only the sidebar.

### What&apos;s On Event Placement

- Source page: `/events`.
- Capture type: wide event page section.
- Must show: filter row, list/calendar toggle, and event card grid.
- Highlight: promoted or sellable event card position.

### Paid Second-Row Event Position

- Source page: profile page or event page where related/promoted events sit under primary content.
- Capture type: page section including profile/event context above and event row below.
- Must show: the paid second-row position in relation to organic event cards.
- Highlight: promoted card or row.

### Homepage Featured Listing

- Source page: homepage Featured Businesses section.
- Capture type: full section width.
- Must show: homepage listing card and any adjacent sponsored/sidebar surface.
- Highlight: homepage featured listing.

### Sponsored Homepage Tile

- Source page: homepage feature/tile section, only if this is a real sellable slot.
- Capture type: tile group in context.
- Must show: surrounding normal discovery tiles for comparison.
- Highlight: sponsored tile.
- Decision needed: confirm whether homepage navigation tiles are paid-eligible or should not be sold.

## Product Decisions Needed

1. Confirm the final sellable placement catalogue.
2. Decide whether homepage tiles are genuinely paid placements or just navigation/discovery tiles.
3. Decide exact pricing and whether it is "introductory launch pricing".
4. Decide whether Bundles are fixed products or just recommended campaigns.
5. Define sponsored labels: Featured, Sponsored, Promoted, Ad, Priority.
6. Define creative requirements per placement.
7. Confirm whether event detail pages will include promoted/related event ads.
8. Confirm analytics promised to advertisers: views, clicks, leads, booking clicks, or only basic reporting.

## Implementation Tasks

1. Rename the catalogue section from "Inventory" to "Available Positions".
2. Group sellable units by real page context.
3. Replace equal-size mockup cards with wide/contextual preview containers.
4. Prepare a screenshot capture script for desktop page sections.
5. Capture each required full-context page view from live/local data.
6. Add highlight overlays to captures or generate faithful annotated renders from those captures.
7. Replace temporary mini mockups with final visuals once captures are approved.
8. Revisit packages, bundle naming, and pricing copy.
9. Run responsive tests and visual review on desktop, tablet, and mobile.
